## Fonctionnalités livrées

- ACCUEIL : attention et missions avant mesures PC/réseau, musique et quotas ; quatre missions simultanées visibles, lien au-delà, événements terminaux pendant 60 s puis retrait. Animations conservées, désactivables et suspendues au masquage. PROJECTS reste un accès discret ; la carte média sans lecteur se compacte.
- MODULES : activation persistante des cinq modules, description, état AXIS, observation/fraîcheur de source, erreur expurgée et accès aux détails. Désactiver PROJECTS ferme uniquement le récepteur AXIS. Les quotas emploient leur vraie date de snapshot, jamais le heartbeat du module ; missions supervisées séparément.
- PARAMÈTRES : minimisation tray, fermeture qui quitte ou masque, restauration optionnelle de page, cadence quota 30/60/120/300 s, animations, notifications et diagnostics. Settings version 1 additive, valeurs V0.9 et champs inconnus préservés ; sauvegardes sérialisées/dédupliquées et attendues avant sortie.
- WINDOWS : garde mutex/event par utilisateur/profil, second lancement restaure la première fenêtre. Tray : afficher, masquer, Accueil, Paramètres et quitter réellement. Arrêt terminal du runtime avant nettoyage ; activation retardée refusée ; fermeture avant Loaded ne réécrit pas un profil non chargé.
- AUTOSTART : option explicite, désactivée par défaut, entrée utilisateur `HKCU/Software/Microsoft/Windows/CurrentVersion/Run`, valeur dédiée `SHINO.AXIS`, chemin EXE réel entre guillemets. Les autres entrées ne sont pas touchées. Un ancien emplacement reste visible et supprimable. Aucun registre écrit au lancement ; option indisponible pour les profils isolés `--data-dir`.
- ÉCOSYSTÈME : observation toutes les 30 s de noms de processus exacts LINK/PERISCOPE/CONTROL/RELAY/HUB, sans lecture des arguments, scan de ports ni requête réseau. Présent ≠ sain ; non détecté ≠ service arrêté. Les processus Python/Node génériques ne sont pas attribués : santé/présence du service restent inconnues.
- FIABILITÉ : après exception runtime, nettoyage puis réessai borné à 5/10/20/40/60 s ; désactivation et fermeture empêchent la reprise. Exceptions affichées par catégorie, sans chemin ni message brut. Cadrans d’Accueil réutilisés et mises à jour graphiques évitées lorsque la fenêtre est masquée.

## Mesures bornées

Package final autonome, profil neuf, PC/NETWORK/MEDIA actifs, CODEX/PROJECTS désactivés, musique absente. Après 5 s d’amorçage, échantillonnage chaque seconde pendant **20.25 s** :

- CPU : **5.4 % d’un cœur**, sans division par le nombre de processeurs.
- Working set moyen : **158.7 Mio**, maximum échantillonné **161.2 Mio** ; mémoire privée moyenne **105.5 Mio**.
- Navigation synthétique : 80 changements de page en 1832 ms, mémoire privée 103,5 → 135,2 Mio avant collecte GC forcée (aucune GC forcée effectuée). Ce delta ne prouve ni fuite ni stabilité prolongée.
- Fermeture WPF avec disque retardé artificiellement de 100 ms : 142 ms. Fermeture de l’EXE autonome avec collecteurs désactivés : **140 ms**.

Protocoles : `tests/Measure-AxisProcess.ps1`, `tests/Verify-AxisPackage.ps1`, harness LifecycleChecks. Mesure courte pendant une session de développement ; bruit CPU des autres applications possible, pas de benchmark système au repos ni de comparaison matérielle certifiée. Aucune revendication de stabilité 24 h/72 h ou de consommation avec compte CODEX/PROJECTS réellement actifs.

## Limites et prochaine action

La santé de LINK/PERISCOPE/CONTROL/RELAY/HUB n’est pas certifiée ; les noms de processus génériques ne permettent pas une attribution sûre. Il n’y a pas de bascule opérationnelle de ces applications. Les contrats et cadences CODEX Live, MEDIA et PROJECTS sont couverts par non-régression synthétique, pas par une nouvelle qualification exhaustive des comptes/lecteurs/extensions réels.

Prochaine action concrète : utiliser ce package pendant une session musicale réelle, sans bascule d’appareil. Réussite : titre/pochette cohérents, pause figée, absence de données résiduelles après fermeture du lecteur, tray/retour fluides ; qualifier ensuite séparément la veille Windows.

**Non effectué :** aucun changement de CONTROL, LINK, PERISCOPE, RELAY/HUB, Android/SmallTV ou extension Chrome ; aucun nouveau producteur, scan réseau, service Windows, modification de ports existants, activation autostart réelle, migration de profil utilisateur, arrêt de processus historique, commit/push/merge ou publication. Le port 44190 et les profils `.runtime/v10-*` sont exclusivement des essais isolés.
