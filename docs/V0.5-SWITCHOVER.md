# V0.5 — Bascule CONTROL vers AXIS (manuelle, non exécutée)

Le package utilise par défaut 127.0.0.1:4187. Il ne tente jamais de prendre 4177, d'arrêter CONTROL ou de modifier l'extension.
La réception de conversations et la synchronisation GitHub automatique sont désactivées jusqu'à une action explicite sur PROJECTS.

## Préparation réversible
1. Fermer les instances AXIS de test. Garder CONTROL et ses fichiers intacts.
2. Depuis PROJECTS, choisir le vrai state.local.json de CONTROL et examiner la prévisualisation. Valider ensuite l'import dans le profil AXIS habituel (%LOCALAPPDATA%\SHINO\AXIS). Ne pas importer des données privées dans un --data-dir situé dans un dépôt Git.
3. Vérifier projets, états importés, sources, groupes, tags, notes, ordre et archivage. Les objets existants ne sont pas écrasés par un nouvel import ; les conflits restent à rapprocher manuellement. Le fichier CONTROL n'est jamais écrit.
4. Configurer localement AXIS_CONTROL_EXTENSION_ID avec l'identifiant exact du collecteur Chrome déjà installé. Conserver le même jeton local via SHINO_CONTROL_TOKEN si le collecteur l'utilise, sans le copier dans le dépôt ni le communiquer dans un rapport. Sans identifiant autorisé, les origines d'extension sont rejetées.
5. Tester d'abord sur 4187 en modifiant volontairement l'endpoint du collecteur pour un essai ciblé, puis remettre sa configuration d'origine.

## Bascule propriétaire
Après qualification des fonctions encore manquantes, arrêter CONTROL soi-même avec son mécanisme habituel. Vérifier que 4177 est libéré. Lancer :
artifacts\Axis-V0.5-win-x64-release\Axis.App.exe --projects-port 4177
AXIS reste lié à 127.0.0.1. Si le port est occupé, le module signale une erreur ; aucun processus n'est arrêté.

Dans PROJECTS, autoriser explicitement la collecte privée, puis déclencher volontairement une collecte de conversation dans Chrome. Vérifier une source mise à jour, sa preuve, le statut/reprise et l'absence de doublon sur la seconde collecte.

## Retour arrière
Désactiver PROJECTS ou quitter AXIS, remettre l'endpoint du collecteur à sa valeur d'origine et relancer CONTROL manuellement. Son stockage original reste disponible. Les nouvelles observations reçues uniquement dans AXIS ne sont pas rétro-importées dans CONTROL : conserver projects.json et projects.json.bak, et relever les conversations à recollecter.

## Limite importante
Cette version reçoit /api/ingest/chatgpt-delta. Les endpoints de catchup-plan/catchup-report, le rattrapage complet d'inventaire et la réparation automatique avancée des mappings ne sont pas portés. Le collecteur peut donc envoyer les deltas ciblés, mais son cycle de rattrapage automatique complet n'est pas encore compatible.
Ne pas considérer V0.5 comme un remplacement de CONTROL à parité complète.
